# Prompt optimization

## The composer's Optimize action (`components/ChatInput.tsx`, `POST /api/prompt/optimize`)
- **It rewrites the draft, it does not send anything.** The button sits in the lower-left cluster beside Attach; a click posts the draft to the route and puts the answer back in the textarea, where it stays the user's to edit. The result line under the composer names what happened (`N project file(s) used`, or why not) and offers **Undo**, which restores the exact previous text. The file count is itself a disclosure (`components/ChatInput.tsx` `OptimizeResultLine`): hovering it on a pointer device, or clicking/focusing it anywhere, opens a small panel above the line listing the retrieved paths (`retrieved[]` from the route, as `<title>` on each row); a `display: none` list stays in the DOM so the paths are testable. It is hidden while a run streams (the composer is for steering then), in `compact` mode, and in shell mode (`!`/`!!`, which pi reads as a command, not a prompt). Disabled reasons are visible text, not a silent no-op: an empty draft, a bare command, a one-token command argument, no model.
- **The one-shot call creates nothing** (`lib/prompt-optimize-run.ts`). No AgentSession, no session file, no sidebar row, no settings write: `runtime.completeSimple()` on the shared `getModelRuntimeWithExtensions()` (so an API key, OAuth login or models.json provider configured in Models works here), `cacheRetention: "none"`, `sessionId: pi-web-optimize-<uuid>`, `maxTokens` 2048, a 90 s timeout, and the caller's `AbortSignal` linked with it. The cheapest thinking level a model supports is used, as titles do (`resolveTitleThinkingLevel()` in `lib/session-title.ts`). Failures are typed `PromptOptimizeError` with a status the route passes on: 400 for a model the runtime does not have, 502 for invalid JSON, commentary, empty text, truncated output, tool calls or other incomplete answers, 504 on the timeout; caller cancellation wins and returns 499. Progress is not streamed: the composer fills in once. The Optimize button is disabled while a request runs; a separate cancel button beside it aborts the call (the abort leaves the draft as it was), so a second click on Optimize can never drop a result.
- **A slash command is never part of the rewrite** (`splitCommandInput()` in `lib/prompt-optimize.ts`). Only a leading `/name` counts, and only when the name is one token: `/usr/local/bin is broken` never splits. The command and the whitespace after it are kept verbatim (`composeCommandInput()`), the command's palette description is sent as context, and the system prompt forbids writing a command itself. **A single-token body is that command's argument, not a description** (`hasOptimizableBody(body, command)`): `/model gpt-5` and `/compact 3` leave the button disabled, and the system prompt tells the model to return an argument (a number, a path, a flag, a name) unchanged when a phrase does reach it. **When the palette is incomplete** (extension, prompt and skill commands load the first time the `/` menu opens) an unknown name is still treated as a command and kept: preserving a prefix the user typed is harmless, rewriting one is not. With the palette loaded, an unknown name is prose (`/tmp is full` is a question). Optimize uses only already-loaded commands: it must never call `onLoadSlashCommands()`, whose session hook can create an AgentSession and send `get_commands`.
- **References and rewrite validation** (`lib/prompt-optimize.ts`). Missing `@file` mentions and URLs are appended to the validated prompt; mentions containing whitespace regain their quotes (`@"my dir/b.ts"`). The model must return exactly one JSON object `{ "text": "..." }`, with no extra fields or surrounding prose/fences. `parseOptimizedText(raw, original)` rejects malformed/empty responses and newly introduced common Chinese/English optimization prefaces, afterwords and thinking tags, including Markdown-wrapped headings. Original matching markers remain permitted up to their original count, so legitimate requests about the optimizer or tag parsing work. This conservative pattern check is not a proof of arbitrary natural-language intent. Invalid results preserve the draft; no automatic retries or model-based review. A valid unchanged result reports that the draft is already clear.
- **The model is remembered per browser** (`lib/prompt-optimize-preference.ts` + `hooks/usePromptOptimizePreference.ts`, localStorage `pi-prompt-optimizer`), like the tool preset: a choice that steers one composer action does not belong in `settings.json`, which the pi CLI reads. The choice and the **Search project files first** switch live in Settings › General (**Prompt optimization**, after Chat), which loads its own list through `GET /api/models?cwd=` as Settings › Agents does; the composer keeps only the button, whose tooltip carries the command rule. Both sides read the one `useSyncExternalStore` store, so a change in the panel reaches an open composer without a remount, another tab's change follows through `storage`, and a blocked localStorage still applies the choice for the page. The default is the composer's current model and search **off**: searching first costs an extra model call and a project search, which made the button feel stuck, so the user opts in. A remembered model the cwd no longer offers falls back to it rather than failing the route.
- **Search mode reads the project locally, then rewrites** (`lib/prompt-retrieval.ts`). (1) A small planner call returns `{"paths": [...], "keywords": [...]}` (`RETRIEVAL_PLAN_SYSTEM_PROMPT`, `parseRetrievalPlan()`, bounded to 8 each; a planner reply that is not usable is not an error). (2) `listProjectFiles()` — the git `ls-files` listing with the readdir fallback `GET /api/file-index` also serves (`lib/project-files.ts`, one 10 s cache on `globalThis.__piFileIndexCache`) — plus `git grep -l -i -F` over the keywords for **content** hits (one 10 s cache per cwd + sorted terms on `globalThis.__piPromptGrepCache`, cleaned on expiry, matching the file-listing window), since a word being in a file beats its being in a folder name. (3) `rankCandidateFiles()` scores guessed paths, content hits and keyword hits, shallower first on ties, skipping binaries, lock files and minified bundles (`isLikelyTextPath()`). (4) `readProjectExcerpts()` reads at most 6 files, 6 KB each, 20 KB in total, through `readRegularFileText()` (a 512 KiB read cap, so a FIFO or a device cannot block the server) and only paths the `/api/files` allow-list covers; a NUL byte means binary and the file is skipped. (5) The second call carries the excerpts as `<project-files>`. Every step fails soft — no cwd, no git, no match — and the rewrite still happens, with `degraded: true` so the composer says no project file matched instead of claiming it read some. Excerpts are the user's own repository, read exactly as pi itself reads it; they are not a new trust boundary (nothing outside the allow-list is read, and nothing is written).
- **The route re-checks what it is given** (`app/api/prompt/optimize/route.ts`): `isApiRequestAllowed()` (403), `hasJsonContentType()` (415), a 20,000-character body and a `provider`+`modelId` pair (400). `cwd` is only a hint for the search step.
- **Conversation isolation and draft ownership**. The optimizer never receives an AgentSession, current session ID, transcript or event writer. Planning and rewriting each use a fresh `pi-web-optimize-<uuid>` request and a new one-user-message context, with no tools; reasoning blocks and planning responses never enter the final draft. Shared model/auth services are not shared conversation state. Only the user’s explicit Send enters the normal conversation path; optimizer notices, retrieved paths and errors stay in composer UI state. Every draft setter synchronously increments a revision and aborts the pending request, including edit-then-Undo back to identical text. A request object token also captures draft key/cwd/revision; results, errors and finalizers check ownership. Layout effects invalidate on key/cwd changes and unmount. Sending clears the draft through the same setter. Cancellation is checked before/after runtime preparation, every retrieval stage and completion; a cancelled planner never degrades into a rewrite. Shared runtime creation and ongoing local filesystem operations are not forcibly terminated, but their results cannot start another stage after cancellation is observed.
