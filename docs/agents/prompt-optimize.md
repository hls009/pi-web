# Prompt optimization

## The composer's Optimize action (`components/ChatInput.tsx`, `POST /api/prompt/optimize`)
- **It rewrites the draft, it does not send anything.** The button sits in the lower-left cluster beside Attach; a click posts the draft to the route and puts the answer back in the textarea, where it stays the user's to edit. The result line under the composer names what happened (`N project file(s) used`, or why not) and offers **Undo**, which restores the exact previous text. The file count is itself a disclosure (`components/ChatInput.tsx` `OptimizeResultLine`): hovering it on a pointer device, or clicking/focusing it anywhere, opens a small panel above the line listing the retrieved paths (`retrieved[]` from the route, as `<title>` on each row); a `display: none` list stays in the DOM so the paths are testable. It is hidden while a run streams (the composer is for steering then), in `compact` mode, and in shell mode (`!`/`!!`, which pi reads as a command, not a prompt). Disabled reasons are visible text, not a silent no-op: an empty draft, a bare command, a one-token command argument, no model.
- **The one-shot call creates nothing** (`lib/prompt-optimize-run.ts`). No AgentSession, no session file, no sidebar row, no settings write: `runtime.completeSimple()` on the shared `getModelRuntimeWithExtensions()` (so an API key, OAuth login or models.json provider configured in Models works here), `cacheRetention: "none"`, `sessionId: pi-web-optimize-<uuid>`, `maxTokens` 2048, a 90 s timeout, and the caller's `AbortSignal` linked with it. The cheapest thinking level a model supports is used, as titles do (`resolveTitleThinkingLevel()` in `lib/session-title.ts`). Failures are typed `PromptOptimizeError` with a status the route passes on: 400 for a model the runtime does not have, 502 for an empty or refused answer, 504 on the timeout. Progress is not streamed: the composer fills in once. The Optimize button is disabled while a request runs; a separate cancel button beside it aborts the call (the abort leaves the draft as it was), so a second click on Optimize can never drop a result.
- **A slash command is never part of the rewrite** (`splitCommandInput()` in `lib/prompt-optimize.ts`). Only a leading `/name` counts, and only when the name is one token: `/usr/local/bin is broken` never splits. The command and the whitespace after it are kept verbatim (`composeCommandInput()`), the command's palette description is sent as context, and the system prompt forbids writing a command itself. **A single-token body is that command's argument, not a description** (`hasOptimizableBody(body, command)`): `/model gpt-5` and `/compact 3` leave the button disabled, and the system prompt tells the model to return an argument (a number, a path, a flag, a name) unchanged when a phrase does reach it. **When the palette is incomplete** (extension, prompt and skill commands load the first time the `/` menu opens) an unknown name is still treated as a command and kept: preserving a prefix the user typed is harmless, rewriting one is not. With the palette loaded, an unknown name is prose (`/tmp is full` is a question — and that click also asks `onLoadSlashCommands()` so the next one is precise).
- **A rewrite that drops an `@file` mention or a link is repaired, not refused** (`collectReferences()` / `missingReferences()`, the composer's own `@` rule: start of text or after whitespace, so an email is not a mention). The missing references are appended back and the result line reports how many were restored; only the rewrite is kept, never a half one that lost what pi reads. Two answers that would otherwise look like a silent no-op are named instead: a rewrite identical to the draft says the prompt is already clear, and a draft that changed while the model worked says the result was dropped. The model is told to copy paths and identifiers verbatim as well, and `parseOptimizedText()` unwraps what a prompt-shaped answer usually carries (a fence around the whole reply, an `Optimized prompt:` / `优化后的提示词：` label, wrapping quotes), while multi-paragraph answers are kept as they are.
- **The model is remembered per browser** (`lib/prompt-optimize-preference.ts` + `hooks/usePromptOptimizePreference.ts`, localStorage `pi-prompt-optimizer`), like the tool preset: a choice that steers one composer action does not belong in `settings.json`, which the pi CLI reads. The choice and the **Search project files first** switch live in Settings › General (**Prompt optimization**, after Chat), which loads its own list through `GET /api/models?cwd=` as Settings › Agents does; the composer keeps only the button, whose tooltip carries the command rule. Both sides read the one `useSyncExternalStore` store, so a change in the panel reaches an open composer without a remount, another tab's change follows through `storage`, and a blocked localStorage still applies the choice for the page. The default is the composer's current model; a remembered model the cwd no longer offers falls back to it rather than failing the route.
- **Search mode reads the project locally, then rewrites** (`lib/prompt-retrieval.ts`). (1) A small planner call returns `{"paths": [...], "keywords": [...]}` (`RETRIEVAL_PLAN_SYSTEM_PROMPT`, `parseRetrievalPlan()`, bounded to 8 each; a planner reply that is not usable is not an error). (2) `listProjectFiles()` — the git `ls-files` listing with the readdir fallback `GET /api/file-index` also serves (`lib/project-files.ts`, one 10 s cache on `globalThis.__piFileIndexCache`) — plus `git grep -l -i -F` over the keywords for **content** hits, since a word being in a file beats its being in a folder name. (3) `rankCandidateFiles()` scores guessed paths, content hits and keyword hits, shallower first on ties, skipping binaries, lock files and minified bundles (`isLikelyTextPath()`). (4) `readProjectExcerpts()` reads at most 6 files, 6 KB each, 20 KB in total, through `readRegularFileText()` (a 512 KiB read cap, so a FIFO or a device cannot block the server) and only paths the `/api/files` allow-list covers; a NUL byte means binary and the file is skipped. (5) The second call carries the excerpts as `<project-files>`. Every step fails soft — no cwd, no git, no match — and the rewrite still happens, with `degraded: true` so the composer says no project file matched instead of claiming it read some. Excerpts are the user's own repository, read exactly as pi itself reads it; they are not a new trust boundary (nothing outside the allow-list is read, and nothing is written).
- **The route re-checks what it is given** (`app/api/prompt/optimize/route.ts`): `isApiRequestAllowed()` (403), `hasJsonContentType()` (415), a 20,000-character body and a `provider`+`modelId` pair (400). `cwd` is only a hint for the search step.
